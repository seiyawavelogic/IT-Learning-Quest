wikiに記載予定

Next.js App Router のベストプラクティスは app/ はルーティングだけに絞ることです。

src/
├── app/                    # ルーティング層のみ
│   ├── layout.tsx
│   ├── page.tsx
│   └── api/
│       └── health/
│           └── route.ts
├── components/             # 再利用可能なUIコンポーネント
│   ├── ui/                 # ボタン・入力欄などの汎用部品
│   └── layout/             # ヘッダー・フッターなど
├── features/               # 機能単位のモジュール
│   └── user/               # 例：ユーザー関連
│       ├── actions.ts      # Server Actions
│       ├── repository.ts   # DBアクセス
│       └── types.ts
├── lib/                    # 共通ユーティリティ
│   └── prisma.ts
└── types/                  # 共通の型定義

---
メリット

┌─────────────┬─────────────────────────────────────┐
│             │                内容                 │
├─────────────┼─────────────────────────────────────┤
│ app/        │ ルーティングだけ → シンプルに保てる │
├─────────────┼─────────────────────────────────────┤
│ components/ │ UIの再利用がしやすい                │
├─────────────┼─────────────────────────────────────┤
│ features/   │ 機能追加・削除が局所的に済む        │
├─────────────┼─────────────────────────────────────┤
│ lib/        │ どこからでも使える共通処理          │
└─────────────┴─────────────────────────────────────┘

信頼性はともかく以下のイメージらしい

Laravelでいうと

app/Http/Controllers  → app
app/Services          → lib
resources/views       → components

みたいな役割分担です。
